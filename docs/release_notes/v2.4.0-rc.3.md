# Spice v2.4.0-rc.3 (October 21, 2026)

Spice v2.4.0-rc.3 is the third release candidate of v2.4.0 for early testing and feedback. Iceberg append refreshes on Spice Cayenne now load rows that a writer commits after newer rows, whatever their `time_column` value. This release also reduces query latency during large refreshes and improves `refresh_mode: caching` performance on Cayenne under high cache-miss rates. It fixes Iceberg schema-only commits, Cayenne storage faults, and AI decisions on Bedrock models.

Highlights in this release:

- [**Iceberg append refreshes follow snapshots**](#iceberg-append-refreshes-follow-snapshots): On Cayenne, append refreshes load the rows that each new snapshot adds, whatever their `time_column` value. Datasets without a primary key on other accelerators also follow snapshots.

These notes cover changes since [v2.4.0-rc.2](v2.4.0-rc.2.md). This release has no new breaking changes. Upgrades from earlier versions still require the [rc.2](v2.4.0-rc.2.md#breaking-changes) and [rc.1](v2.4.0-rc.1.md#breaking-changes) migration guidance.

## What's New in v2.4.0-rc.3

### Iceberg Append Refreshes Follow Snapshots

Before this release, `refresh_mode: append` on an Iceberg dataset read only the rows after `max(time_column)` minus `refresh_append_overlap`. A writer that committed rows out of time order left those rows behind. Only a full refresh loaded them.

On Spice Cayenne, an append refresh now reads the data files that each snapshot added since the last refresh. It reads them whatever their `time_column` values are. Datasets without a primary key on other accelerators get the same behavior. The refresh uses the same deduplication as every append, so a late, older version of a row does not replace a newer stored version. No new setting is necessary.

```yaml
datasets:
  - from: iceberg:s3://my-bucket/warehouse/db/events
    name: events
    time_column: event_time
    acceleration:
      enabled: true
      engine: cayenne
      refresh_mode: append
      primary_key: id
```

- **Supported configurations:** Cayenne follows snapshots for every dataset. DuckDB, SQLite, and the other accelerators follow snapshots only for datasets without a primary key. Their keyed datasets continue to read by time.
- **Fallback:** The runtime reads by time for one refresh when it cannot follow the table history. Examples are an overwrite without a primary key, an expired snapshot, or a rollback. `dataset_acceleration_refresh_fallbacks{reason}` counts each fallback.

`refresh_append_overlap` now applies only to time-filtered reads. See [Data Refresh](https://spiceai.org/docs/features/data-acceleration/data-refresh) and the [Iceberg data connector](https://spiceai.org/docs/components/data-connectors/iceberg).

## Fixes and Improvements

### Iceberg

- **Schema-only commits:** Spice now reads Iceberg tables whose last commit only added, renamed, or dropped a column. Before, queries on these tables failed.

### Cayenne

- **File listings:** Queries no longer fail with `Failed to open Vortex file … not found` after a first load, a full refresh, a retention pass, or an append. Queries also no longer miss appended rows.
- **MySQL CDC initial load:** MySQL changes-mode datasets with maintained aggregates now complete their initial snapshot on large tables.
- **High cache-miss rates:** Cayenne datasets with [`refresh_mode: caching`](https://spiceai.org/docs/features/data-acceleration/refresh-modes/caching) now keep up with high miss rates, with lower latency and no dropped cache writes.

### Runtime

- **Open file limit:** `spiced` now raises its soft open file limit to the hard limit at startup on Unix. This prevents `Too many open files` errors under many client connections.
- **Distributed queries:** In a [Spice.ai Enterprise](https://docs.spice.ai/docs/enterprise) cluster, a task that waits on a slow HTTP source lends its executor slot to other queries.

### AI and Models

- **Bedrock decisions:** The `ai_*` decision functions and `/v1/decisions` now work with [Bedrock models](https://spiceai.org/docs/components/models/bedrock).

### Observability

- **Trace IDs in exported logs:** All exported log records of a query now carry the trace ID that the client set with `spice-trace-id` or `traceparent`.

## Upgrading

Once release artifacts are available, select v2.4.0-rc.3 explicitly with the CLI, Docker tag, or Helm chart version.

### CLI

```console
spice upgrade v2.4.0-rc.3
```

### Docker

```console
docker pull spiceai/spiceai:2.4.0-rc.3
```

See [Docker Hub](https://hub.docker.com/r/spiceai/spiceai/tags) for available tags.

### Helm

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.4.0-rc.3
```

### Homebrew and AWS Marketplace

Homebrew and AWS Marketplace follow their published versions. To select this release candidate, use an explicit version through the CLI or Docker.

```console
brew upgrade spiceai/spiceai/spice
```

Spice is also available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
