# Spice v2.3.4 (October 26, 2026)

Spice v2.3.4 is a security patch release. It fixes CVE-2026-111497, an out-of-bounds write in the Brotli decoder of the DuckDB that Spice bundles. A malformed Brotli-compressed Parquet file can trigger the write when DuckDB reads it, for example through the DuckDB data connector or the DuckDB accelerator. Upgrade if DuckDB in your deployment can read Parquet files that you do not control. The release also fixes stale cached results for parameterized queries in some cache setups. No configuration changes are needed.

This release also fixes two more security issues. Spice now rejects DOCX, XLSX, and PPTX documents that have inconsistent ZIP headers (CVE-2026-115905). Spice also stops trusting two more eMudhra root CAs. If you index XLSX documents, read [Breaking Changes](#breaking-changes): some extracted text changes, and some XLSX files now fail to parse.

## What's New in v2.3.4

### Brotli Decoder Fix in the Bundled DuckDB (CVE-2026-111497)

DuckDB no longer writes out of bounds when it decodes a malformed Brotli-compressed Parquet page. The decoder now rejects an invalid block switch with the `BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH` error. Before this release, the decoder continued with stale block-type state, and a crafted file could make it write outside its buffer.

Most Parquet reads in Spice do not go through DuckDB. The fix matters where DuckDB itself decodes a Parquet file that an untrusted party can supply.

Spice builds DuckDB v1.4.4 from source, so this release carries the fix before a DuckDB release includes it. The fix is a port of [duckdb/duckdb#27791](https://github.com/duckdb/duckdb/pull/27791), which ports [google/brotli@0ed4268a](https://github.com/google/brotli/commit/0ed4268a4401abcb4472096340477cf4af7d1a2b).

### Two More eMudhra Root CAs Are No Longer Trusted

Spice no longer trusts the `emSign Root CA - C1` and `emSign ECC Root CA - C3` root certificates. An attacker can forge a certificate that chains to these roots. An attacker on the network path can use such a certificate. The attacker can then intercept connections from a client that still trusts these roots.

This change applies to outbound TLS connections that use the root store built into Spice (`webpki-roots`). It does not change TLS connections that use the operating system certificate store. The `ca-certificates` package of the operating system controls that store. v2.3.3 removed `emSign ECC Root CA - G3` with `webpki-roots` 1.0.10. The upstream change follows the [CCADB removal of these CAs](https://bugzilla.mozilla.org/show_bug.cgi?id=2083709).

### Office Documents with Inconsistent ZIP Headers Are Rejected (CVE-2026-115905)

Spice no longer parses a DOCX, XLSX, or PPTX document if the ZIP headers in the document disagree. Such a document now fails to parse with an `InternalParsingError`, and Spice does not index its content. This fix matters if an untrusted party can write Office documents to a source that Spice parses.

A ZIP file stores the name of each entry two times: in a local file header and in the central directory. In `zip` 9.0.4 and earlier, different ZIP readers can trust different headers. A crafted file can then show different content to different tools. The advisory is [GHSA-m665-v7pm-7grj](https://github.com/zip-rs/zip2/security/advisories/GHSA-m665-v7pm-7grj) ("zip cloaking").

This fix also updates `calamine`, the XLSX parser, from 0.28 to 0.37. This update changes some of the XLSX text that Spice extracts. Refer to [Breaking Changes](#breaking-changes).

### Cached Results for Parameterized Queries Are Refreshed Again

Spice now refreshes a stale cached result for a parameterized query in the background, as `stale_while_revalidate_ttl` specifies. This affected two setups: `cache_key_type: sql`, and a client that sends the `Spice-Cache-Key` header.

Before this release, the background query lost the parameter values and failed with `Placeholder '$1' was not provided a value for execution`. Spice then served the stale result for the full `item_ttl` plus `stale_while_revalidate_ttl` window. Each stale request also started another background query that failed. The results were old, but not wrong.

## Breaking Changes

**XLSX text that Spice extracts can change, and some XLSX files now fail to parse.** This release updates `calamine`, the XLSX parser, from 0.28 to 0.37. If you index or search XLSX documents, compare the extracted text after you upgrade. The changes are:

- An XLSX file without the `_rels/.rels` part now fails to parse. Files from Office applications have this part.
- A boolean cell with a value other than `0`, `1`, `false`, or `true` is now an error, and the document fails to parse. Before this release, Spice read the value as `true`.
- Spice now removes leading and trailing whitespace from `<t>` text in shared and inline strings. Text in a `<t>` element with `xml:space="preserve"` does not change.
- Spice now decodes `_xHHHH_` escapes, for example `_x000D_` to `\r`. Spice also changes `\r\n` to `\n` in strings. Formula string results get the same changes.
- A cell with an empty `<v/>` is now empty. Before this release, the cell showed the first shared string.
- Spice now reads rich-text runs (`<r>`) after a first plain `<t>`. Spice also reads `inlineStr` cells with CDATA.

The text of date cells and the order of sheets do not change.

## Upgrading

To upgrade to v2.3.4, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.3.4` image:

```console
docker pull spiceai/spiceai:2.3.4
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.3.4
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
