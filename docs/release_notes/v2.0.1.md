# Spice v2.0.1 (June 17, 2026)

Spice v2.0.1 is a patch release that improves Amazon S3 and object-store dataset reliability, fixes accelerated-table resolution behind metadata and index provider wrappers (including in distributed clusters), correctly scopes request-context identity across the managed query runtime, and speeds up Apache Iceberg reads with parallel file scanning.

## What's New in v2.0.1

### Faster Iceberg Reads with Parallel File Scanning

The [Apache Iceberg](https://spiceai.org/docs/components/catalogs/iceberg) reader now scans data files in parallel ([#11331](https://github.com/spiceai/spiceai/pull/11331)), improving read throughput and latency for Iceberg tables that span many files.

### Amazon S3 & Object-Store Reliability

Three fixes improve [S3](https://spiceai.org/docs/components/data-connectors/s3) and object-store dataset behavior:

- **Refresh-skip restored behind provider wrappers** ([#11339](https://github.com/spiceai/spiceai/pull/11339)): ETag/Version-based refresh-skip is no longer lost when a dataset's provider is wrapped (for example by metadata enrichment), eliminating redundant data loads of unchanged S3 objects.
- **Retry when source files are not yet available** ([#11342](https://github.com/spiceai/spiceai/pull/11342)): an object-store dataset whose source files are not present at startup now retries and becomes ready once the data appears, instead of failing permanently.
- **Path-style addressing for dotted bucket names** ([#11347](https://github.com/spiceai/spiceai/pull/11347)): on standard AWS, buckets whose names contain dots now default to path-style addressing, avoiding TLS wildcard certificate errors under virtual-hosted-style HTTPS.

### Accelerated-Table Resolution Through Wrappers

Datasets that carry column or table metadata (descriptions) or full-text-search / embedding indexes are registered wrapped in provider decorators. Two fixes ensure the underlying [accelerated table](https://spiceai.org/docs/components/data-accelerators) is resolved through those wrappers:

- **Acceleration endpoints** ([#11345](https://github.com/spiceai/spiceai/pull/11345)): `/v1/datasets/{name}/acceleration/refresh` (and the related update-refresh-sql, partition-filters, and snapshots endpoints) now resolve accelerated tables behind the metadata-enrichment wrapper, instead of reporting `Table is not accelerated`.
- **Distributed clusters** ([#11226](https://github.com/spiceai/spiceai/pull/11226)): the [distributed query](https://spiceai.org/docs/features/distributed-query) coordinator now distributes accelerated tables wrapped by metadata or index providers to executors, instead of silently federating the read back to the source.

### Request-Context Scoping Across the Managed Query Runtime

Query planning and execution dispatched to the managed (CPU) query runtime now run under the originating request context ([#11253](https://github.com/spiceai/spiceai/pull/11253)). Previously the context was lost on the managed runtime, causing identity-dependent behavior — identity UDFs, per-principal results-cache namespacing, and task-history attribution — to fall back to the anonymous context when authentication and the managed runtime were enabled.

## Upgrading

To upgrade to v2.0.1, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.0.1` image:

```console
docker pull spiceai/spiceai:2.0.1
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.0.1
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
