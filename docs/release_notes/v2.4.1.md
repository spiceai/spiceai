# Spice v2.4.1 (October 29, 2026)

Spice v2.4.1 is a security patch release. It stops data sources from sending Spice's requests to internal addresses. An HTTP server, an Iceberg REST catalog, or an AWS Glue table can no longer send requests and credentials to private, loopback, or link-local hosts. Request header values also no longer create metric series, so a caller cannot grow the memory of the runtime with distinct header values. Upgrade if Spice reads from HTTP endpoints or catalogs that you do not control, or if untrusted clients can reach its endpoints.

This release also fixes more security issues. HTTP connector passwords no longer appear in errors. Spice now limits the memory that a malformed Parquet file, an MCP tool result, a compressed HTTP response, or a scalar function call can use. The other fixes cover WASM user-defined functions on arm64, TLS certificate reload, and Docker image packages. Read [Breaking Changes](#breaking-changes) before you upgrade: some Iceberg, URL table, HTTP, and MySQL setups need a setting change, and some metric labels are removed.

## What's New in v2.4.1

### Internal Addresses Are Refused for Catalog Storage, HTTP Redirects, and URL Tables

Spice no longer sends a request to a private, loopback, or link-local address only because a data source names that address. The checks apply to these paths:

- **Iceberg REST catalogs**: Spice refuses a storage endpoint or region that the catalog vends when it differs from the Spicepod value and reaches an internal host. Spice connects only to the addresses that its DNS check approved. Spice refuses a redirect from vended storage to an internal host, and it removes `Authorization` and `Cookie` headers when a redirect changes the origin.
- **AWS Glue**: Spice rejects a table location that is not `s3://`.
- **HTTP and HTTPS datasets**: A redirect to a host name that resolves to an internal address fails with `Refused to connect to <host>`.
- **URL tables**: With `runtime.params.url_tables: enabled`, Spice checks every redirect and every resolved address. An `s3`, `abfs`, `abfss`, `gs`, or `gcs` URL table cannot set an endpoint or credentials in the URL fragment.

Storage endpoints and regions that the Spicepod sets keep working. `SPICE_URL_TABLE_ALLOW_PRIVATE_HOSTS=true` turns off the checks for Iceberg and URL tables. See [Breaking Changes](#breaking-changes) for the setups that need a setting.

### HTTP Connector Passwords Stay out of Errors

Errors from `http` and `https` file datasets no longer include the password from the URL. This applies to the warning log, `/v1/datasets?status=true`, and Cloud Connect. Spice now sends the user name and `http_password` in an `Authorization: Basic` header, only to the origin that the dataset configures. CSV, Parquet, and other file reads through the HTTP connector now authenticate, and the server no longer answers them with 401.

### Compressed HTTP Responses Have a Limit

Spice refuses a compressed HTTP response after it decodes more than 64 MiB at more than 100 times the bytes received. In a test, a 583 KB gzip response grew the runtime to 2,464 MB of memory. With this fix, the runtime refused the response at 232 MB. The check applies to the HTTP connector, OAuth2 token exchange, Unity Catalog, Databricks, and the Debezium schema registry. Token and metadata responses also have a 128 MiB limit on decoded size.

### Memory Limits for Parquet Files, MCP Tool Results, and Scalar Functions

A small malformed file or a single query can no longer make the runtime allocate gigabytes of memory or crash:

- **Parquet pages**: A page that declares more than 64 MiB and more than 1,000 times its compressed bytes fails with an error. In a test, 8 concurrent scans of a 34 KB file used 4,271 MiB of memory. With this fix, they used 166 MiB.
- **Parquet metadata**: A footer list that declares more elements than the file can hold fails with a decode error. In a test, one malformed footer used 22.6 GiB of memory. With this fix, it used 0.43 GiB.
- **Parquet schema depth**: A schema that nests more than 100 levels fails with `Parquet schema nesting depth exceeds the maximum of 100`. A deeper schema overflowed the stack and stopped the runtime.
- **MCP tool results**: An MCP tool call fails when the result is larger than 16 MiB. The runtime logs a warning that names the MCP server. In a test, a 200 MB result used 2,423 MB more memory. With this fix, it used less than 1 MB more.
- **Scalar functions**: `repeat`, `lpad`, `rpad`, `array_repeat`, `array_resize`, `range`, and `generate_series` reserve their output from `runtime.query.memory_limit`. A call that does not fit fails with `Resources exhausted`. In a test with a 512 MiB limit, `length(repeat('a', 1e9))` used 3.9 GB. With this fix, the query failed, and peak memory was 97 MB.

### Request Headers No Longer Create Metric Series

Spice no longer copies `User-Agent` or W3C `baggage` values into metric labels. Any caller could send these headers, also to `/health`, and each distinct value created new series in memory. In a test, 500 requests with distinct values grew `/metrics` from 365 to 34,865 series. With this fix, the count stays at 365. The `client` label now has a fixed set of values. Refer to [Breaking Changes](#breaking-changes).

### WASM User-Defined Functions on arm64 (GHSA-mghf-wjfp-p5xm)

Wasmtime 48.0.7 fixes a sandbox escape for [WASM user-defined functions](https://spiceai.org/docs/features/functions) on arm64 hosts. On aarch64, the Cranelift compiler could jump to the wrong target for a large Wasm `br_table` instruction. The advisory is [GHSA-mghf-wjfp-p5xm](https://github.com/advisories/GHSA-mghf-wjfp-p5xm). It does not affect x86_64 hosts.

### TLS Certificate Reload Rejects a Mismatched Key

A certificate rotation no longer breaks TLS handshakes when the new certificate does not match the private key. The runtime keeps the current certificate, logs a warning that names both files, and increments `runtime_tls_reload_total{result="key_mismatch"}`. At startup, a mismatched pair stops the runtime. See [TLS](https://spiceai.org/docs/api/tls).

The `spice` CLI HTTP commands, such as `status`, `datasets`, and `refresh`, now trust the CA in `--tls-root-certificate-file`. A certificate failure reports the TLS error and a fix, not `The Spice runtime is unavailable`.

### Docker Images Get Current Packages

Each release build of the `spiceai/spiceai` image now runs `apt-get upgrade`. The build cache can no longer reuse a package layer from before a security update, such as [DSA-6572-1](https://security-tracker.debian.org/tracker/DSA-6572-1). The CUDA image moves from `nvidia/cuda:12.6.0-cudnn-runtime-ubuntu24.04`, from August 2024, to `12.9.2` with current packages.

### MySQL Connections Are Replaced After 5 Minutes

[MySQL](https://spiceai.org/docs/components/data-connectors/mysql) datasets and catalogs now replace each pooled connection after `mysql_connection_max_lifetime`. Thus the pool spreads across the servers behind a load-balanced hostname, such as an Aurora reader endpoint. The default is `5m`, and `0s` keeps connections open. Spice does not close a connection while a query uses it. With `mysql_connection_string`, `mysql_pool_min` and `mysql_pool_max` now apply. See [MySQL deployment](https://spiceai.org/docs/components/data-connectors/mysql/deployment#connection-pool-sizing).

### Dependency Updates

- `wasmtime`: 47.0.3 → 48.0.7. This update fixes GHSA-mghf-wjfp-p5xm.
- `rustls`: 0.23.45 → 0.23.46.
- `aws-lc-rs`: 1.18.1 → 1.18.2. The bundled AWS-LC moves from v5.7.0 to v5.11.0.
- `webpki-root-certs`: 1.0.10 → 1.0.11. This update removes the `emSign Root CA - C1` and `emSign ECC Root CA - C3` roots. v2.4.0 already removed them from `webpki-roots`.
- `http-body-limit`: a new crate that limits decoded HTTP response bodies.
- `arrow-rs` (Spice fork): `2e2cc330` → `2124b9e8`. This update adds the Parquet page, metadata, and schema-depth limits. Arrow remains at v59.3.0.
- CUDA Docker image base: `nvidia/cuda` 12.6.0 → 12.9.2.

DataFusion remains at v55.2.0 and Arrow remains at v59.3.0.

## Breaking Changes

**Iceberg and Glue storage endpoints.** Spice refuses a catalog-vended endpoint on an internal host, with an error that names the endpoint. These setups need a change:

- A REST catalog, such as a local Nessie, vends a private or loopback MinIO endpoint. Set `iceberg_s3_endpoint` and `iceberg_s3_region`.
- A REST catalog vends only a region, and S3 resolves to private addresses through a VPC interface endpoint. Set `iceberg_s3_endpoint` to the regional S3 endpoint.
- A Glue table location is `s3a://`, `http://`, or `https://`. Use an `s3://` location.

**URL table fragments.** A URL table cannot set `endpoint`, `allow_http`, access keys, or proxy settings in the URL fragment. `region`, `url_style`, `auth`, `account`, and `client_timeout` still work. Configure a dataset for a custom endpoint. A URL table behind a proxy on a private address needs `SPICE_URL_TABLE_ALLOW_PRIVATE_HOSTS=true`.

**Compressed HTTP responses.** Very sparse rows can compress at more than 100:1, and Spice refuses them past 64 MiB. To turn off the check for a dataset, add `Accept-Encoding: identity` to `http_headers`.

**Metric labels.** The runtime no longer records the `user_agent`, `client_version`, `client_system`, or `baggage` labels. The `client` label is one of `spice`, `repl`, `spicepy`, `spice-rs`, `gospice`, `spice.js`, `spice-java`, `spice-dotnet`, or `other`. Update dashboards and alerts that use these labels.

**MySQL pool.** A dataset with `mysql_connection_string` and no pool settings uses 1 to 5 connections, not 10 to 100. Set `mysql_pool_max` if the dataset needs more concurrent queries. A non-integer or conflicting pool setting now fails the dataset.

**Memory limits.** Parquet files with pages, footer lists, or schema nesting past the limits in [Memory Limits](#memory-limits-for-parquet-files-mcp-tool-results-and-scalar-functions) fail to load. MCP tool results larger than 16 MiB fail. Queries with these scalar functions fail when their output does not fit `runtime.query.memory_limit`.

**TLS and the CLI.** The runtime does not start when the TLS certificate does not match its private key. A missing or invalid `--tls-root-certificate-file` fails the CLI command.

## Upgrading

To upgrade to v2.4.1, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.4.1` image:

```console
docker pull spiceai/spiceai:2.4.1
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.4.1
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
