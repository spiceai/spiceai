# Spice v2.1.4 (August 5, 2026)

Spice v2.1.4 is a patch release that fixes two DuckDB acceleration failures — datasets with fixed-offset timezone columns (such as Iceberg `timestamptz`) failing to load, and the periodic retention loop failing with a binder error — and a rare runtime crash when a query task was cancelled while a Vortex I/O result was being delivered.

## What's New in v2.1.4

### DuckDB Acceleration of Fixed-Offset Timezone Columns

A DuckDB-accelerated dataset whose time column carried an Arrow fixed-offset timezone previously failed to load and stayed permanently unhealthy with `Unknown TimeZone '+00:00'`. DuckDB resolves `AT TIME ZONE` through a zone-name lookup, so it rejects every offset spelling — and Iceberg maps every `timestamptz` column to `+00:00`, so Iceberg datasets accelerated into DuckDB with an append refresh were the most common case. Zero-offset spellings (`+00:00`, `-00:00`, `+0000`, `-0000`, `+00`, `-00`) denote UTC and now load correctly. Non-zero offsets still fail loudly rather than risk a wrong instant.

### DuckDB Retention with Compound Predicates

The periodic retention check against a DuckDB accelerator could fail every interval with `Binder Error: No function matches the given name and argument types 'epoch_ms(BOOLEAN)'` when the retention predicate combined a timestamp comparison with another condition. The DuckDB timestamp normalization was rewriting every binary expression, including `AND`/`OR`; it is now applied only to comparisons, so retention evicts the correct rows without error.

### Task Cancellation Stability

An internal task cancellation that interleaved with a completing Vortex I/O operation could corrupt memory and crash the runtime with a `SIGSEGV` on a worker thread — at arbitrary uptime and uncorrelated with load or client activity, because what matters is only that a cancellation coincides with a completion. The one-shot channels carrying task and segment-read results now use tokio's channel, which does not release its waker while the sender can still call it.

## Upgrading

To upgrade to v2.1.4, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.1.4` image:

```console
docker pull spiceai/spiceai:2.1.4
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.1.4
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
