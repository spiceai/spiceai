# Spice v2.1.1 (July 16, 2026)

Spice v2.1.1 is a patch release focused on reliability and correctness. It resolves a possible deadlock that affected datasets with partitioned Cayenne acceleratons, corrects SQL results-cache misses for empty result sets, restores Bedrock embedding provider parameters, and speeds up repeated queries on multi-file datasets.

## What's New in v2.1.1

### Cayenne Partitioned Dataset Deadlock Fix

[Cayenne](https://spiceai.org/docs/components/data-accelerators/cayenne) datasets configured with `partition_by` could deadlock during their initial refresh and never become ready ([#11825](https://github.com/spiceai/spiceai/pull/11825)). Non-partitioned tables and small partitioned tables were unaffected. The root cause was a deadlock between the partition routing and the global Vortex encode budget introduced in v2.1.0. 

### Cayenne Zero-Row Append Refresh Stability

An idle append refresh — one where no source rows are newer than the current `max(time_column)` — wrote no Vortex files, so the expected snapshot directory was never created. The subsequent `fsync` on that directory failed with `ENOENT`, marking the dataset unhealthy ([#11710](https://github.com/spiceai/spiceai/pull/11710)). The fix skips the snapshot sequence record and protected-snapshot publish when the write carried no rows.

### SQL results cache hits for empty results

The SQL results cache never stored empty result sets ([#11699](https://github.com/spiceai/spiceai/pull/11699)). Queries that legitimately return no rows — `WHERE id = 999` with no match, `WHERE 1=0`, `LIMIT 0` — were re-executed against the source on every request. The root cause was that the cache write gate checked whether the result contained any record batches, not if the stream completed successfully. 

### Faster Repeated Queries on Multi-File Datasets
Object store datasets using parquet now cache Parquet footer statistics across queries ([#11793](https://github.com/spiceai/spiceai/pull/11793)). This reduces the frequency of Parquet footer parsing during planning, subsequently heavily reducing planning latency for certain query patterns (e.g. `COUNT(*)`). 

### Embedding Parameter regression Fixes

v2.1.0 introduced explicit definitions across embedding component parameters (i.e. `.embbedings[].params`). This introduced regressions for AWS bedrock parameters `truncation` and `truncation_mode` that caused panics.

## Upgrading

To upgrade to v2.1.1, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.1.1` image:

```console
docker pull spiceai/spiceai:2.1.1
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.1.1
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
