# Spice v1.2.0 (Apr 28, 2025)

Spice v1.2.0 is a major release which includes upgrades to DataFusion v45 and DuckDB v1.2.2, including improvements in query peformance, and introduces parameterized query support across SQL and HTTP APIs and accelerated views. Numerous bug fixes and dependency upgrades further improve stability and performance.

## DataFusion v45 Improvements

Spice.ai is built on the DataFusion query engine. Highlights in the v45 release include:

- **Improved Performance 🚀**: DataFusion became the fastest single node engine for querying Apache Parquet files in the clickbench benchmark, with over 33% performance improvement between DataFusion 33 and DataFusion 45. The integration of Arrow StringView, now enabled by default, significantly boosts performance for workloads involving variable length string and binary data, especially with Parquet files.

- **Improved Quality 📋**: DataFusion quality continues to improve with the addition of the SQLite sqllogictest suite (over 5 million SQL statements tested per push), explicit logical plan invariant checks, and more extensive prerelease testing.

- **New Functions ✨**: New SQL functions such as `show functions`, `to_local_time`, `regexp_count`, `map_extract`, `array_distance`, `array_any_value`, `greatest`, `least`, and `arrays_overlap`.

See the [DataFusion 45.0.0 release notes](https://datafusion.apache.org/blog/2025/02/20/datafusion-45.0.0/) for more details.

The Spice.ai policy is to upgrade to the latest minus 1 release to ensure adequate testing and quality control. Spice expects to upgrade to DataFusion v46 in the Spice v1.3.0 release.

## What's New in v1.2.0

- **DuckDB v1.2.2 Upgrade**: DuckDB has been upgraded from v1.1.3 to v1.2.2, which includes new compression methods, performance improvements, and optimizations.

See the [DuckDB v1.2.0](https://duckdb.org/2025/02/05/announcing-duckdb-120.html) release notes for more details.

- **Parameterized Queries**: Spice now supports parameterized queries via the Flight SQL API and HTTP API, including support for `$1` and `?` placeholder syntax. Logical plans of SQL statements are cached for subsequent queries.

  See [SQL Query API](https://spiceai.org/docs/api/HTTP/post-sql) and [Flight SQL documentation](https://spiceai.org/docs/api/flight-sql).

- **Accelerated Views**: Views can now be accelerated in addition to datasets for significantly improved performance for compute heavy views.

  Example `spicepod.yaml`:

  ```yaml
  views:
    - name: accelerated_view
      acceleration:
        enabled: true
        engine: duckdb
        primary_key: id
        refresh_check_interval: 1h
      sql: |
        select * from dataset_a
        union all
        select * from dataset_b
  ```

  See [Data Acceleration documentation](https://spiceai.org/docs/features/data-acceleration/).

- **Memory Usage Metrics & Configuration**: Runtime now records memory usage as a metric, and a new runtime `memory_limit` parameter is available. The memory limit parameter applies specifically to the runtime and should be used in addition to existing memory usage configuration, such as `duckdb_memory_limit`. Memory usage for queries beyond the memory limit will spill to disk.

- **New Worker Component**: Workers in the Spice runtime represent configurable units of compute that help coordinate and manage interactions between models and tools. Workers currently help implement model fallback and error handling and load balancing across multiple models.

Workers are configured in the `workers` section of the `spicepod.yaml` file. Each worker definition includes a name, description, and a list of models or tools it encapsulates.

**Example `spicepod.yaml` configuration:**

```yaml
workers:
  - name: round-robin
    description: |
      Distributes requests between 'foo' and 'bar' models in a round-robin fashion.
    models:
      - from: foo
      - from: bar
  - name: fallback
    description: |
      Attempts 'bar' first, then 'foo', then 'baz' if previous models fail.
    models:
      - from: foo
        order: 2
      - from: bar
        order: 1
      - from: baz
        order: 3
```

- **`spice chat` CLI improvements**: The `spice chat` CLI command now supports an optional `--temperature` parameter and allows for one-shot chat requests using `spice chat <message>`.

- **Additional type support**: Added support for Postgres JSON type and DuckDB Dictionary type.

- **Additional Improvements**:
  - Added specific image tags for selecting specific memory allocators tailored to specific use-cases, including `jemalloc`, `sysalloc`, and `snmalloc`.
  - Improved error handling and logging for chat and model operations.

## Breaking Changes

### DuckDB v1.2.0

- The `random` function now uses a larger state, so fixed seeds will produce different values than previous DuckDB versions.
- `map['entry']` now returns a value instead of a list. Use `map_extract` to return a list, and `map_extract_value` (alias for `[]`) to return a value.
- The indexing for `list_reduce` is fixed: the index now points to the last lambda parameter and starts from 1.

No other breaking changes in this release.

## Upgrading

To upgrade to v1.2.0, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:1.2.0` image:

```console
docker pull spiceai/spiceai:1.2.0
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai
```
