# Spice v1.3.0 (May 19, 2025)

Spice v1.3.0 brings significant performance improvements, enhanced reliability, and a more streamlined experience. This release focuses on making data queries faster and more efficient while improving security and usability.

## DataFusion v46 Highlights

Spice.ai is built on the DataFusion query engine. The v46 release brings:

- **Faster Performance 🚀**: DataFusion 46 introduces significant performance enhancements, including a 2x faster `median()` function for large datasets without grouping, 10–100% speed improvements in `FIRST_VALUE` and `LAST_VALUE` window functions by avoiding sorting, and a 40x faster `uuid()` function. Additional optimizations, such as a 50% faster `repeat()` string function, accelerated `chr()` and `to_hex()` functions, improved grouping algorithms, and Parquet row group pruning with `NOT LIKE` filters, further boost overall query efficiency.

- **New range() Table Function**: A new table-valued function `range(start, stop, step)` has been added to make it easy to generate integer sequences — similar to PostgreSQL’s generate_series() or Spark’s range(). Example: `SELECT * FROM range(1, 10, 2);`

- **UNION [ALL | DISTINCT] BY NAME Support**: DataFusion now supports `UNION BY NAME` and `UNION ALL BY NAME`, which align columns by name instead of position. This matches functionality found in systems like Spark and DuckDB and simplifies combining heterogeneously ordered result sets.

  Example:

  ```sql
  SELECT col1, col2 FROM t1
  UNION ALL BY NAME
  SELECT col2, col1 FROM t2;
  ```

See the [DataFusion 46.0.0 release notes](https://datafusion.apache.org/blog/2025/03/24/datafusion-46.0.0/) for details.

Spice.ai upgrades to the latest minus one DataFusion release to ensure adequate testing and stability. The next upgrade to DataFusion v47 is planned for Spice v1.4.0 in June.

## What's New in v1.3.0

- **Improved Results Cache Performance & Hashing Algorithm:** In addition to performance optimizations for results caching, the Runtime now supports specifying an alternative hashing algorithm, `ahash`. The `siphash` algorithm is used by default, which can be changed by specifying a Runtime parameter:

  ```yaml
  runtime:
    results_cache:
      hashing_algorithm: ahash
  ```

  Using `ahash` as the cache key hashing algorithm results in improved performance, particularly for large queries or query plans. In addition to using `ahash`, the results cache performance optimizations have improved the 99th percentile request latency and total requests/second for queries with large query results (100k+ cached rows). These charts displays the 99th percentile request latency and total requests/second tested against the [TPCH Query #17](https://github.com/spiceai/spiceai/blob/trunk/crates/test-framework/src/queries/tpch/q17.sql) on a scale factor 5 dataset (30+ million rows, 5gb dataset size):

- **Query Processing**: The main query path has been optimized, reducing overhead and improving response times for simple queries by 10-20%.

- **DuckDB Acceleration**: A bug was fixed in the DuckDB acceleration engine that caused query failures when querying across datasets that were accelerated into multiple DuckDB files under high concurrency.

- **Container Security**: The container image implements enhanced sandboxing by running as a non-root user and slimming down the image to only include the necessary dependencies.

## Upgrading

To upgrade to v1.3.0, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:1.3.0` image:

```console
docker pull spiceai/spiceai:1.3.0
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai
```
