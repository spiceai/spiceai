# Spice v2.4.3 (November 16, 2026)

Spice v2.4.3 is a patch release. It fixes file datasets that served wrong or missing data, and it fixes 27 security advisories in dependencies. When a CSV file with a header row changed its column order, the runtime read values into the wrong columns. A full refresh of a deleted or emptied file or S3 source replaced the acceleration with zero rows. A `${ secrets:… }` reference that did not resolve loaded the dataset with an empty value.

The release also upgrades DataFusion to 55.3.0, hardens the install scripts, and fixes other wrong results and query errors in specific setups. Users of file datasets, S3 datasets, and secret references should upgrade. Before you upgrade, read [Breaking Changes](#breaking-changes). Some datasets that loaded in v2.4.2 now fail with an error that names the cause.

## What's New in v2.4.3

### File Datasets Keep Correct Data When Source Files Change

[File](https://spiceai.org/docs/components/data-connectors/file) and object-store datasets, such as [S3](https://spiceai.org/docs/components/data-connectors/s3), no longer serve wrong or missing data after their source files change. These fixes apply to federated and accelerated datasets.

- **CSV columns bind by header name.** A CSV or TSV dataset with `has_header: true` (the default) now reads each column by its header name. Before this release, the runtime read columns by position. When a file changed its column order, the runtime read values into the wrong columns. The dataset stayed `Ready`, with no warning. A CSV with `has_header: false` still binds by position.
- **A deleted or emptied source fails the refresh.** When a refresh finds no data files for a dataset, it now fails and the acceleration keeps its last data. The dataset status changes to `Error`, and the log names the dataset and path: `No data files are yet available for dataset …`. Before this release, a full refresh replaced the acceleration with zero rows, and the dataset stayed `Ready`. This covers an emptied directory or prefix, a prefix with only its folder marker, and a deleted single S3 object. A header-only CSV file or a zero-row Parquet file still loads as zero rows.
- **A renamed or removed column fails the refresh.** A refresh that reads every file now fails when no source file has a column of the dataset. The acceleration keeps its last data. Before this release, the refresh replaced the column values with `NULL`, with no error. This check covers Parquet, ORC, JSON, CSV, and TSV files. CSV and TSV files need a header row.
- **JSON sources and federated queries.** A missing JSON key fails the refresh only when the files also have new keys, which is the pattern of a rename. A JSON source with zero records can still clear the acceleration. A federated query returns `NULL` for a missing column. It logs one warning that names the dataset and the column.
- **The file watcher sees more types of writes.** With `file_watcher: enabled`, the acceleration now refreshes after an atomic replace (write a temporary file, then rename it). It also refreshes after appends that arrive close together and after a large in-place rewrite. Before this release, the watcher missed later writes after a rename. It also dropped the last write of a burst and could refresh from an empty or partial file. The watcher now watches the parent directory and waits 400 ms after the last write before it refreshes.

### Secret References That Do Not Resolve Fail the Dataset

A dataset or catalog with a `${ secrets:… }` reference that does not resolve now fails to load. The error names the parameter and the reference, and it never shows a secret value. Before this release, the runtime replaced the reference with an empty value and loaded the dataset. For example, `file_format: ${ secrets:FMT }` with `FMT` not set loaded a 25-row CSV file as a one-row text table. The dataset reported `Ready`, and `/v1/ready` returned 200.

This applies only to dataset and catalog `params`. Other datasets continue to load. When a secret store returns an error, the runtime retries the load. An empty or whitespace `file_format` now also fails with an error that lists the valid formats.

If a secret is optional on purpose, define it with an empty value, such as `FMT=` in the environment or a `.env` file. A secret with an empty value counts as resolved. For details, see [Secret Stores](https://spiceai.org/docs/components/secret-stores).

### Dependency Security Updates

This release upgrades dependencies to fix 27 security advisories. The advisories affect these areas:

- **MCP server and client (`rmcp`).** SSRF in the OAuth client (RUSTSEC-2026-0457). Unbounded memory use in the Streamable HTTP server and clients (RUSTSEC-2026-0461, RUSTSEC-2026-0462).
- **FTP connector (`suppaftp`).** Command injection through line breaks in control-channel arguments (RUSTSEC-2026-0271).
- **HTTP/2 (`h2`).** Denial of service through empty `DATA` frames (RUSTSEC-2026-0258).
- **QUIC (`quinn-proto`).** RUSTSEC-2026-0338, RUSTSEC-2026-0340, RUSTSEC-2026-0343, RUSTSEC-2026-0523, and RUSTSEC-2026-0524.
- **Compression (`zstd`, `zstd-safe`).** Data from one stream in another stream, and uninitialized memory (RUSTSEC-2026-0391, RUSTSEC-2026-0398, RUSTSEC-2026-0403).
- **WebAssembly (`wasmtime`).** Type confusion, panics, and unchecked memory use between components (RUSTSEC-2026-0422, RUSTSEC-2026-0423, RUSTSEC-2026-0424).
- **File parsing.** Panics and unbounded allocation on malformed XLSX files (`calamine`, RUSTSEC-2026-0436). Exponential and quadratic Markdown parsing (`pulldown-cmark`, RUSTSEC-2026-0414, RUSTSEC-2026-0433).
- **Archive extraction (`zip` 3).** Symlink and permission escapes, and a crash (RUSTSEC-2026-0367, RUSTSEC-2026-0368, RUSTSEC-2026-0369, RUSTSEC-2026-0429). The runtime no longer depends on `zip` 3.
- **Other.** Timing side channels in `crypto-bigint` and `ctutils` (RUSTSEC-2026-0387, RUSTSEC-2026-0385). Unsound `AsyncFd` constructors in `tokio` (RUSTSEC-2026-0386). A `libz-sys` build script that leaked environment variables (RUSTSEC-2026-0418).

Two behavior changes come with these upgrades:

- An FTP download that the server reports as failed now returns an error. Before this release, it could return truncated data.
- The MCP server returns the JSON-RPC error `-32602` with HTTP 200 for an unknown tool. Before this release, it returned HTTP 400. The [MCP specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) requires HTTP 200.

### Install Scripts Check Downloads

The install scripts now check the sha256 of each download before they extract it. This applies to `install.sh`, `install-spiced.sh`, and `Install.ps1`. If the sha256 does not match, the install stops and installs nothing. For a 2.4.x release, the scripts compare the download with the sha256 that GitHub recorded for the release asset. Before this release, the scripts did not check downloads.

The install scripts also have these fixes:

- **Shell syntax in an install directory.** `install.sh`, `install-spiced.sh`, and `install-nightly.sh` no longer run an install directory that contains shell syntax as a command. Before this release, `SPICE_INSTALL_DIR='/tmp/x; touch /tmp/pwned'` ran `touch /tmp/pwned`, as root when the install used `sudo`.
- **Missing `/usr/local/bin`.** `install-spiced.sh` now asks for `sudo` before it creates a missing install directory. Before this release, a user who was not root stopped with `Permission denied`. This occurred on a Mac with Apple silicon and no `/usr/local/bin`, for example.
- **Windows `PATH`.** `Install.ps1` no longer fails when the user `PATH` is not set. It now compares whole `PATH` entries. Before this release, a similar directory such as `.spice\bin2` stopped the installer from adding `.spice\bin`.

`spice install <version>` and `spice upgrade --version <version>` no longer fail with `Release not found` for a release older than the 30 newest releases. The CLI now finds the release by its tag.

The new download checks can stop some installs that worked before. See [Breaking Changes](#breaking-changes).

### DataFusion 55.3.0

The runtime now uses DataFusion 55.3.0. The upgrade fixes these wrong results and query errors:

- **Sort order.** A query with a filter on a lossy cast or on wrapping arithmetic of an `ORDER BY` column no longer returns rows out of order. The planner removed the sort for these filters.
- **`LEAD` and `LAG` with `IGNORE NULLS`.** These window functions now return the correct row.
- **Sort-merge outer joins.** An outer join with a filter that runs as a sort-merge join no longer fails with `declared as non-nullable but contains null values`.
- **Other fixes.** The upgrade also fixes sort-merge joins on float keys and the output order of outer joins. It fixes row counts from async UDFs, the IPC framing of spill files, and the memory accounting of grouped `MIN` and `MAX`.

The upgrade changes how Hive partition columns read `__HIVE_DEFAULT_PARTITION__`. Some file accelerations need an action after the upgrade. See [Breaking Changes](#breaking-changes).

### Caching Mode Returns Every Requested Key

An [HTTP dataset](https://spiceai.org/docs/components/data-connectors/https) with [`refresh_mode: caching`](https://spiceai.org/docs/features/data-acceleration/refresh-modes/caching) no longer returns only the cached rows for a query that names both cached and uncached request keys. This applied to an `IN` list or an `OR` of the same column on `request_path`, `request_query`, or `request_body`. The runtime did not request the missing keys from the source, and the query returned no error. The runtime now fetches only the missing keys and returns them with the cached rows.

A query that finds some of its keys in the cache also obeys `max_request_partitions`. A query over the limit fails with the same error as a query with no cached keys, and it sends no request.

### Other Bug Fixes

- **Large `/v1/sql` results and the memory limit.** A buffered `/v1/sql` response no longer uses memory outside [`runtime.query.memory_limit`](https://spiceai.org/docs/reference/memory). Before this release, in a test with a 256 MiB limit, one `text/plain` request raised peak memory from 0.7 GB to 7.4 GB. A result that does not fit in the limit now returns HTTP 503 with `The query result is too large to buffer in memory for this response`. The runtime buffers `text/plain`, CSV, the `vnd.*` formats, JSON with union columns, and the final result of a `BEGIN … COMMIT` transaction. Other JSON responses stream and do not change.
- **Views after a Spicepod reload.** A view no longer returns rows from the old version of a dataset after a Spicepod reload replaces or removes that dataset. The view now reads the dataset that the Spicepod declares, or fails when the dataset is gone. This also applies to a view that reads the dataset in a subquery or through another view.
- **`/v1/ready` after a Spicepod reload.** `/v1/ready` no longer returns 503 for a component that a reload removed before it loaded.
- **Delta Lake struct filters.** A `WHERE` filter on a struct field no longer fails with `Error during planning: Field a not found in struct`. This applied to a federated [Delta Lake](https://spiceai.org/docs/components/data-connectors/delta-lake) dataset on a table with column mapping (`delta.columnMapping.mode` set to `name` or `id`).
- **Maps inside struct columns.** A key lookup into a map inside a struct column, such as `som['mm']['k']`, no longer fails on a federated Parquet file dataset. The query failed with `Internal error: PhysicalExpr Column references column 'som' …`.
- **`time_column: last_modified`.** A dataset with `time_column: last_modified` no longer fails with `time_column 'last_modified' was not found`. Spice renamed this metadata column to `_last_modified` in v2.0. The runtime now uses `_last_modified` when the data has no `last_modified` column, and it logs a deprecation warning. `time_format` defaults to `timestamptz` for `_last_modified`.
- **Refresh requests with an empty body.** `POST /v1/datasets/{name}/acceleration/refresh` with an empty body and `Content-Type: application/json` no longer fails with HTTP 400. This occurred when a proxy added that header to a request with no body. An empty or whitespace body now gives the default refresh. Malformed JSON still returns 400, and an unknown `refresh_mode` still returns 422.
- **SQL parameters in search functions.** A query with a parameter such as `$1` in a `text_search`, `vector_search`, or `rrf` argument no longer fails with a placeholder error. The runtime now puts the parameter values into the arguments before it plans the query. The plan cache does not keep these plans. For the search functions, see [Search](https://spiceai.org/docs/features/search).

### Dependency Updates

- DataFusion: 55.2.0 → 55.3.0.
- ADBC: 0.24 → 0.25. The Spice fork now carries one patch, because ADBC 0.25 has the statement-cancel fix.
- `rmcp`, `suppaftp`, `h2`, `quinn-proto`, `zstd`, `wasmtime`, `calamine`, `tokio`, and other crates: patched releases for the advisories in [Dependency Security Updates](#dependency-security-updates).

## Breaking Changes

**Secret references that do not resolve.** A dataset or catalog with a `${ secrets:… }` reference in `params` that does not resolve now fails to load. Other datasets continue to load. If a secret is optional on purpose, define it with an empty value, such as `FMT=`. An empty `file_format` value also fails.

**Hive `__HIVE_DEFAULT_PARTITION__` reads as `NULL`.** With `hive_partitioning_enabled: true`, rows under a `col=__HIVE_DEFAULT_PARTITION__/` directory now return `NULL` for that partition column. Partition columns are now nullable. `WHERE col IS NULL` matches these rows, and `WHERE col = '__HIVE_DEFAULT_PARTITION__'` does not.

An existing `mode: file` acceleration of such a dataset fails to refresh after the upgrade. The error is `Invalid batch column … has null but schema specifies non-nullable`. The dataset continues to serve its existing data. To fix it:

- With `refresh_mode: full`, set `on_schema_change: sync_all_columns`.
- With `refresh_mode: append` or `changes`, rebuild the acceleration.

Other Hive datasets continue to refresh. They log a startup warning and report the partition column as `NOT NULL` until you rebuild the acceleration.

**File datasets fail on missing files or columns.**

- A refresh that finds no data files now fails, and the acceleration keeps its last data. A federated query of a dataset with no data files now returns an error that names the dataset and path. Before this release, both returned zero rows.
- A refresh that reads every file now fails when no file has a column of the dataset. Before this release, the refresh loaded `NULL` values.

**Install scripts.**

- An install stops when the script cannot get the expected sha256, for example when the GitHub API request fails or hits its rate limit. For a 2.4.x release, the script always sends this request, also for a pinned version such as `bash -s 2.4.3`. To fix it, set `GITHUB_TOKEN`. To install with no check, set `SPICE_INSTALL_ALLOW_UNVERIFIED=1`.
- An install of v1.3.1 or older stops, because GitHub recorded no sha256 for these releases. Set `SPICE_INSTALL_ALLOW_UNVERIFIED=1` to install them.
- An install always stops on a sha256 mismatch. No setting changes this.
- `Install.ps1` writes its output with `Write-Output`, not `Write-Host`. A failed install now throws an error. Before this release, it exited with status 0.

**Large buffered `/v1/sql` results.** A CSV, `text/plain`, or `vnd.*` response from `/v1/sql` that does not fit in `runtime.query.memory_limit` now returns HTTP 503. Before this release, it returned HTTP 200 and used memory outside the limit. To get a large result over HTTP, request JSON. The runtime streams JSON when the result has no union columns.

**MCP unknown tools.** The MCP server returns HTTP 200 with the JSON-RPC error `-32602` for an unknown tool. Before this release, it returned HTTP 400.

## Upgrading

To upgrade to v2.4.3, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.4.3` image:

```console
docker pull spiceai/spiceai:2.4.3
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.4.3
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
