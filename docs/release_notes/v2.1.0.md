Spice v2.1.0 is the next minor release of Spice, bringing significant optimisation and tuning of the **Spice Cayenne** accelerator, scaling and resilience improvements to PostgreSQL logical replication, support for Iceberg catalogs and broadcast joins in distributed query, and improvements from the upgrade to DataFusion v54, Arrow v58.3, and Vortex v0.74.

Highlights in v2.1.0 include:

- **[Self-Tuning Cayenne Accelerator](#self-tuning-cayenne-accelerator)** — closed-loop `auto`/`adaptive` tuning that adapts to hardware, schema, and live workload, plus maintained aggregates with incremental retraction ([#11213](https://github.com/spiceai/spiceai/pull/11213), [#11310](https://github.com/spiceai/spiceai/pull/11310), [#11235](https://github.com/spiceai/spiceai/pull/11235))
- **[High-Throughput Cayenne CDC](#high-throughput-cayenne-cdc)** — in-memory CDC tier, dedicated compaction runtime, and write-path optimizations that cut replication lag on high-volume CDC workloads ([#11206](https://github.com/spiceai/spiceai/pull/11206), [#11130](https://github.com/spiceai/spiceai/pull/11130))
- **[PostgreSQL Replication at Scale](#change-data-capture--htap)** — multiple `changes`-mode datasets share a single replication slot, unchanged-TOAST recovery, and resilient reconnects across rolling deploys ([#11255](https://github.com/spiceai/spiceai/pull/11255), [#11293](https://github.com/spiceai/spiceai/pull/11293))
- **[Distributed Query](#distributed-query)** — distributed Ballista scans of Iceberg catalog tables and broadcast joins for small dimension tables ([#11419](https://github.com/spiceai/spiceai/pull/11419), [#11245](https://github.com/spiceai/spiceai/pull/11245))
- **[DataFusion v54](#performance--query-engine)** — upgrade to DataFusion v54, Arrow v58.3, and Vortex v0.74 ([#11360](https://github.com/spiceai/spiceai/pull/11360), [#11118](https://github.com/spiceai/spiceai/pull/11118))


## What's New in v2.1.0

### Self-Tuning Cayenne Accelerator

The [Spice Cayenne](https://spiceai.org/docs/components/data-accelerators/cayenne) accelerator becomes self-tuning:

- **Closed-Loop Adaptive Tuning**: New `auto` and `adaptive` modes tune Cayenne from hardware, schema, and a closed feedback loop ([#11213](https://github.com/spiceai/spiceai/pull/11213)), driving toward operator SLOs — replication lag, freshness, query latency, and queries-per-hour ([#11310](https://github.com/spiceai/spiceai/pull/11310)), with further adaptive-tuning and schema-safety improvements ([#11237](https://github.com/spiceai/spiceai/pull/11237)).
- **Maintained Aggregates**: Cayenne can maintain aggregates incrementally ([#11235](https://github.com/spiceai/spiceai/pull/11235)), with incremental retraction to keep them current under updates ([#11389](https://github.com/spiceai/spiceai/pull/11389), open at draft).
- **Metadata Aggregate Pushdown**: Whole-table `SUM`/`AVG`/`COUNT`/`MIN`/`MAX` are folded directly from statistics ([#11414](https://github.com/spiceai/spiceai/pull/11414), open at draft).
- **Listing-Time Pruning & Scan Pushdown**: Listing-time pruning, per-file statistics, and scan pushdown reduce work on large tables ([#11234](https://github.com/spiceai/spiceai/pull/11234)).
- **Extended Schema Inference**: Deeper schema inference is wired into Cayenne compaction sharding and sorting ([#11284](https://github.com/spiceai/spiceai/pull/11284)), with auto-applied inferred sort so compaction clusters data for pruning ([#11236](https://github.com/spiceai/spiceai/pull/11236)).

Enable self-tuning with the `cayenne_tuning` parameter — `auto` derives configuration from the detected hardware and inferred schema, while `adaptive` additionally runs a per-table closed-feedback controller that adapts flush caps, the in-memory CDC tier, compaction cadence, and write concurrency to live workload:

```yaml
datasets:
  - from: postgres:public.orders
    name: orders
    acceleration:
      engine: cayenne
      refresh_mode: changes
      params:
        cayenne_tuning: adaptive # 'auto' (static, env- + schema-derived) or 'adaptive' (closed-loop)
```

### High-Throughput Cayenne CDC

A major focus of v2.1 is Cayenne write-path throughput for change-data-capture (HTAP) workloads:

- **In-Memory CDC Tier**: A new in-memory CDC tier and follow-ups cut replication lag on hot upsert tables ([#11191](https://github.com/spiceai/spiceai/pull/11191), [#11206](https://github.com/spiceai/spiceai/pull/11206), [#11278](https://github.com/spiceai/spiceai/pull/11278)), with bounded mem-tier checkpointing and O(1) per-scan deletion views ([#11249](https://github.com/spiceai/spiceai/pull/11249), [#11232](https://github.com/spiceai/spiceai/pull/11232)) and a two-phase off-fence checkpoint on the ingest path ([#11247](https://github.com/spiceai/spiceai/pull/11247)).
- **Dedicated Compaction Runtime**: A dedicated compaction runtime with CDC pipelining and protected snapshots isolates compaction from query and ingest paths ([#11130](https://github.com/spiceai/spiceai/pull/11130)), with parallelized deletion-vector writes and per-batch directory-barrier coalescing ([#11200](https://github.com/spiceai/spiceai/pull/11200)) and size-aware parallel encode for protected-snapshot compaction ([#11201](https://github.com/spiceai/spiceai/pull/11201)).
- **Incremental Protected Snapshot Compaction**: Incremental compaction of protected snapshots (used in Cayenne's  merge-on-read deletion index) ([#11326](https://github.com/spiceai/spiceai/pull/11326), [#11361](https://github.com/spiceai/spiceai/pull/11361), [#11325](https://github.com/spiceai/spiceai/pull/11325)) reduces disk usage and query performance.
- **Smaller WAL & Metadata-Only Publish**: `cayenne_insert_record` table IDs are stored as 16-byte raw-UUID BLOBs, cutting CDC WAL volume ~34% ([#11223](https://github.com/spiceai/spiceai/pull/11223)); upsert commits publish metadata-only, dropping per-key insert records ([#11260](https://github.com/spiceai/spiceai/pull/11260)); transient staged CDC deltas are light-encoded ([#11311](https://github.com/spiceai/spiceai/pull/11311)).
- **Delta-Write Encoding Levels**: A new `cayenne_delta_encoding` setting (default `auto`) selects delta-write encoding, and `compression_strategy: zstd` is now fully wired ([#11199](https://github.com/spiceai/spiceai/pull/11199)).
- **In-Memory CDC Sharding**: PK-hash intra-apply sharding parallelizes in-memory CDC apply ([#11421](https://github.com/spiceai/spiceai/pull/11421), open at draft).
- **Scan Safety Under Write**: In-flight scans are ref-counted so snapshot GC can't delete Vortex files mid-read ([#11321](https://github.com/spiceai/spiceai/pull/11321)); in-RAM scan parallelism, query admission control, and sound scan output ordering improve read behavior under sustained CDC ([#11332](https://github.com/spiceai/spiceai/pull/11332), [#11299](https://github.com/spiceai/spiceai/pull/11299)).

Delta-write encoding effort and Vortex compression are tunable per accelerator. `cayenne_delta_encoding: auto` (the default) size-gates fresh CDC/append writes — small deltas use a light scheme and are re-encoded during compaction — or pin an explicit level `0..10` (`7` is the full default cascade); `cayenne_compression_strategy` selects the Vortex compression:

```yaml
acceleration:
  engine: cayenne
  refresh_mode: changes
  params:
    cayenne_delta_encoding: auto # 'auto' (default), or pin a level 0..10 (7 = full cascade)
    cayenne_compression_strategy: zstd # 'btrblocks' (default) or 'zstd'
```

### Distributed Query

[Distributed Query](https://spiceai.org/docs/features/distributed-query) gains:

- **Distributed Iceberg Catalog Scans**: Ballista distributes scans of Iceberg catalog tables across executors ([#11419](https://github.com/spiceai/spiceai/pull/11419), open at draft).
- **Broadcast Joins**: Small dimension tables are broadcast to executors for distributed joins ([#11245](https://github.com/spiceai/spiceai/pull/11245)).

### Change Data Capture & HTAP

PostgreSQL logical replication (CDC, `refresh_mode: changes`, [introduced in v2.0](https://spiceai.org/docs/components/data-connectors/postgres)) gets significant scaling and resilience work in v2.1:

- **Shared Replication Slot**: Multiple `refresh_mode: changes` [PostgreSQL](https://spiceai.org/docs/components/data-connectors/postgres) datasets on the same connection can name the same `pg_replication_slot` to share a single replication slot, walsender decoder, and publication, with decoded changes multiplexed by `(schema, table)` to each dataset ([#11255](https://github.com/spiceai/spiceai/pull/11255)). This collapses the slot count from one-per-dataset to one — staying well under Postgres's default `max_replication_slots = 10`. 
```yaml
datasets:
  - from: postgres:public.orders
    name: orders
    params:
      pg_db: mydb
      pg_replication_slot: spice_cdc # shared slot name
    acceleration:
      refresh_mode: changes
  - from: postgres:public.customers
    name: customers
    params:
      pg_db: mydb
      pg_replication_slot: spice_cdc # same name -> one slot, walsender & publication
    acceleration:
      refresh_mode: changes
```

- **Unchanged-TOAST Recovery**: Under `REPLICA IDENTITY FULL`, when an `UPDATE` leaves a large TOASTed column unchanged, pgoutput sends an "unchanged" marker; Spice now fills that value from the old tuple — its old value is its current value — so updates no longer error or drop columns ([#11293](https://github.com/spiceai/spiceai/pull/11293)). Without an old tuple, the error persists with a hint to enable `REPLICA IDENTITY FULL`.
- **Transient Walsender Contention**: Slot-contention errors during rolling deploys — `SQLSTATE 55006` ("replication slot is active for PID") and `53300` ("requested standby connections exceeds max_wal_senders") — are now classified as transient and retried with backoff instead of fatally terminating the stream ([#11293](https://github.com/spiceai/spiceai/pull/11293)). Replication connections are also released at shutdown start (not process exit), freeing walsender seats for replacement instances.
- **Debezium Schema Evolution**: Fixes for Debezium schema-evolution support ([#11095](https://github.com/spiceai/spiceai/pull/11095)).

### AI & LLM

- **Native GLM Support with Distributed Inference**: Native GLM model support with surfaced `reasoning_content` ([#11400](https://github.com/spiceai/spiceai/pull/11400)), including tensor-parallel GLM inference ([#11406](https://github.com/spiceai/spiceai/pull/11406), open at draft). Load a GLM model with `model_type: glm4` (`glm4moe` and `glm4moelite` are also supported):

```yaml
models:
  - name: glm
    from: huggingface:huggingface.co/THUDM/glm-4-9b-chat
    params:
      model_type: glm4
```

  For large models, GLM inference can be distributed across nodes (tensor parallelism) via the mistral.rs pure-TCP `ring` all-reduce backend — no NCCL/system dependency. This is a [Spice.ai Enterprise](https://docs.spice.ai/docs/enterprise) feature requiring the `distributed` build. Run the same model on each node, changing only `node_rank`:

```yaml
models:
  - name: glm
    from: huggingface:huggingface.co/THUDM/glm-4-9b-chat
    params:
      model_type: glm4
      distributed_backend: ring
      nodes: 10.0.4.21,10.0.4.22 # ordered host/IP per rank; the ring backend currently requires exactly 2
      node_rank: 0 # rank of THIS node in [0, world_size); rank 0 serves the API. Set node_rank: 1 on 10.0.4.22
```

- **NSQL Context Endpoint**: A new `GET /v1/nsql/context` endpoint returns the SQL dialect, dataset schemas (with optional sample rows), and registered functions that Spice injects into natural-language-to-SQL (`POST /v1/nsql`) requests — useful for inspecting or caching exactly what the model sees ([#11075](https://github.com/spiceai/spiceai/pull/11075)):

```bash
# Inspect the context injected into /v1/nsql requests (sample_limit default 3, max 100)
curl "http://localhost:8090/v1/nsql/context?sample_limit=3"
```

Returns the dialect, per-dataset schema (keys, indexes, searchable columns), the registered function inventory, and sample rows (abbreviated):

### Performance & Query Engine

[Apache DataFusion](https://datafusion.apache.org/) is upgraded to **v54** ([#11360](https://github.com/spiceai/spiceai/pull/11360)) via v53.1, alongside **Arrow v58.3** and **Vortex v0.74** ([#11118](https://github.com/spiceai/spiceai/pull/11118)), with a Vortex pin bump adding intra-file decode split and a per-execution kernel cache ([#11314](https://github.com/spiceai/spiceai/pull/11314)). Federation deny-list enforcement and catalog DDL are restored after the DataFusion upgrades ([#11294](https://github.com/spiceai/spiceai/pull/11294), [#11375](https://github.com/spiceai/spiceai/pull/11375)).

### Observability

- **Per-Dataset Query Attribution**: The `query_executions` metric gains a `datasets` dimension ([#11138](https://github.com/spiceai/spiceai/pull/11138)).
- **HTAP Diagnostics**: Improved HTAP replication diagnostics on non-convergence ([#11100](https://github.com/spiceai/spiceai/pull/11100)).
- **Cayenne Write Observability**: Write-phase observability for the in-memory CDC tier ([#11278](https://github.com/spiceai/spiceai/pull/11278)).

### Notable Bug Fixes

- **Cayenne Utf8View**: The Utf8View read schema avoids a hash-join offset overflow ([#11379](https://github.com/spiceai/spiceai/pull/11379)).
- **Cayenne metastore**: `cayenne_metastore: turso` is honored for partitioned tables and the dataset checkpoint ([#11365](https://github.com/spiceai/spiceai/pull/11365)).
- **Dual-write detection**: Dual-write accelerated tables are detected behind the metadata-enrichment wrapper ([#11351](https://github.com/spiceai/spiceai/pull/11351)).
- **`digest_many` collisions**: Values are length-prefixed so column boundaries can't collide ([#11288](https://github.com/spiceai/spiceai/pull/11288)).
- **Turso WAL checkpoint**: WAL checkpoints route through the native Turso connection ([#11048](https://github.com/spiceai/spiceai/pull/11048)).
- **TLS status probe**: The status check probes the metrics endpoint over HTTPS when TLS is enabled ([#11393](https://github.com/spiceai/spiceai/pull/11393)).
- **Snapshot engine mappings**: `PartitionedDuckDB` is included in snapshot engine mappings ([#11045](https://github.com/spiceai/spiceai/pull/11045)).
- **Async query chunk offsets**: `/v1/queries` chunk `row_offset` uses the cumulative offset rather than `chunk_index * chunk_size` ([#11398](https://github.com/spiceai/spiceai/pull/11398), open at draft).

## Upgrading

To upgrade to v2.1.0, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.1.0` image:

```console
docker pull spiceai/spiceai:2.1.0
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.1.0
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
