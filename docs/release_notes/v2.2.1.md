# Spice v2.2.1 (September 1, 2026)

Spice v2.2.1 is a patch release focused on the footprint and correctness of accelerated data. Cayenne maintenance tasks improved to bound space overhead in more cases, several query paths that could return a wrong or missing row are fixed, DuckDB and HTTP datasets keep their memory bounded, and new metrics make Cayenne's maintenance decisions and storage growth visible.

## What's New in v2.2.1

### Cayenne Reclaims Disk and Metastore Space

A [Cayenne](https://spiceai.org/docs/components/data-accelerators/cayenne) acceleration under steady writes could grow on disk indefinitely. Superseded state of several kinds — inline tombstones, retired snapshots, metadata rows describing compacted-away snapshots, and orphaned deletion vectors — was made unreachable but never removed. Each gap is now closed, and no configuration change is required.

Retention predicates that call `now()` — for example `retention_sql: DELETE FROM t WHERE arrival_time < now() - INTERVAL '7 days'` — now work. Previously the maintenance pass failed silently on every write and deleted nothing, so a default configuration never evicted expired rows.

### Correct Results on More Query Paths

A predicate `DELETE` on a Cayenne upsert table could destroy rows the predicate does not match, because the delete matched against stored files rather than against the visible row set and so could remove a primary key it reached through a superseded row version. Only an upsert table and a `DELETE` with a non-primary-key predicate were needed to hit it.

Three other paths returned wrong answers without reporting an error. `json_get_int` and `json_get_float` returned NULL for every negative JSON number on all previously shipped versions. `Date64` columns compared a millisecond count as a nanosecond one when deciding whether to read a Vortex file, and the same comparison failed the scan outright for `Date32`. A pushed-down search filter on a timezone-aware timestamp column was truncated to whole milliseconds, so a DuckDB-backed search returned a different set of rows than the caller asked for.

Spice-only UDFs such as `json_get_str` no longer federate to ADBC sources. Since v2.2.0 they were pushed into the SQL sent to sources such as BigQuery and failed as unknown functions, and `query_federation: disabled` was validated and then ignored. Both are restored, and JSON extraction functions can now be translated into BigQuery SQL and pushed down. Cayenne also no longer risks a duplicate row for a declared primary key after a failed index rebuild, no longer answers a distributed `COUNT(*)` from a count that a just-published commit has made short, and plans point lookups on CDC datasets again.

### Bounded Memory for DuckDB and HTTP Datasets

The bundled DuckDB is downgraded to v1.4.4. On v1.5.5 the write path an accelerated dataset uses grew memory without bound at a steady row count until the write failed out of memory. Concurrent queries also now survive a file-mode DuckDB swap, which previously failed queries against any other file-mode acceleration on the same runtime.

The [HTTP data connector](https://spiceai.org/docs/components/data-connectors/http) kept every fetched response in a map that was never pruned. Because the keys are request-shaped, memory was unbounded by construction on an API-proxy workload, and invisible to both `runtime.caching` limits and metrics. The cache is now bounded in bytes with per-entry expiry, reports per-dataset metrics, and honours `no-store` and `no-cache`.

### Cayenne Maintenance and Storage Metrics

Cayenne's maintenance passes mostly decide *not* to run, and each correct decline leaves the table slightly larger. Those declines were debug log lines and nothing countable, so "nothing is reclaiming" could not be told apart from "reclamation ran and found nothing."

A new set of metrics on the `cayenne` meter, served at `/metrics` when `spiced` is started with `--metrics <addr>`, reports whether each pass ran and why it declined (`cayenne_compaction_outcome_total`, `cayenne_maintenance_outcome_total`), how much it reclaimed (`cayenne_maintenance_reclaimed_{files,bytes,rows}_total`), and where the disk and memory are going (`cayenne_storage_*`, `cayenne_data_dir_*`, `cayenne_metastore_*`).

### Change Data Capture and Write-Back

A CDC-accelerated dataset that writes back to its PostgreSQL source no longer double-applies its own write. The logical-replication stream echoes each write-back transaction, so Spice now records the transaction ids it issues and drops the matching changes from the stream, including after a slot reconnect replays them. Durable write-back also now delivers for a table whose primary key is a single `BIGINT` column, which previously never reached the source.

MySQL accelerations rebuild from a purged binlog position when `mysql_replication_invalid_checkpoint_behavior: restart` is set, even alongside `mysql_replication_initial_snapshot: disabled`. Previously a durable acceleration silently resumed from the current head, permanently keeping rows that were deleted at the source inside the unreachable window. Append refresh on Vortex and Cayenne also resumes correctly again, where a watermark read could error and leave the dataset no longer appending.

## Breaking Changes

No breaking changes.

One behavior change is worth noting before upgrading:

- **The bundled DuckDB is downgraded from v1.5.5 to v1.4.4** to fix unbounded memory growth on the accelerated write path. SQL features introduced in DuckDB v1.5.x are no longer available to DuckDB-accelerated datasets.

## Cookbook Updates

No new cookbook recipes.

The [Spice Cookbook](https://spiceai.org/cookbook) includes more than 104 recipes to help you get started with Spice quickly and easily.

## Upgrading

To upgrade to v2.2.1, use one of the following methods:

**CLI**:

```console
spice upgrade
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

**Docker**:

Pull the `spiceai/spiceai:2.2.1` image:

```console
docker pull spiceai/spiceai:2.2.1
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.2.1
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i).
