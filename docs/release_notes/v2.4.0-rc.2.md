# Spice v2.4.0-rc.2 (October 15, 2026)

Spice v2.4.0-rc.2 is the second release candidate for v2.4.0. It adds SQL decision functions and an OpenAI-compatible `/v1/decisions` API, catalog-free Iceberg reads, and `runtime.state` startup checks. It changes how the SQL results cache ages entries, and it improves Cayenne performance and correctness.

Highlights in v2.4.0-rc.2 include:

- [**Decisions in SQL**](#decisions-in-sql-and-v1decisions): `ai_if`, `ai_probability`, `ai_classify`, `ai_score`, and `ai_decide`, and an OpenAI-compatible `/v1/decisions` endpoint.
- [**Iceberg Without a Catalog**](#iceberg-without-a-catalog): read a table from its root directory, or from a pinned metadata file.
- [**Shared State Location**](#shared-state-location-runtimestate): startup checks, a folder for each feature, and snapshots under `runtime.state`.
- [**SQL Results Cache TTL**](#sql-results-cache-ttl): cached results age on TTL. A refresh no longer invalidates them.
- [**Cayenne**](#cayenne): runtime-wide adaptive tuning, faster keyed loads, and settings that apply on restart.
- [**Rate Control and Responses API**](#rate-control-and-responses-api): fairer rate-control queues, and `/v1/responses` returns Spice tool calls.

## What's New in v2.4.0-rc.2

### Decisions in SQL and `/v1/decisions`

> TODO(DRI): confirm the function signatures against the docs PR.

Five SQL functions return typed answers from any model in the Spicepod. A decision model or a chat model can answer:

| Function                                  | Returns                                                       |
| ----------------------------------------- | ------------------------------------------------------------- |
| `ai_if(input, condition)`                 | `BOOLEAN`, true when the probability of "yes" is above 0.5    |
| `ai_probability(input, condition)`        | `DOUBLE` from 0 to 1                                          |
| `ai_classify(input, labels)`              | `VARCHAR`, always one of `labels`                             |
| `ai_score(input, instructions, levels)`   | `DOUBLE`, a probability-weighted score                        |
| `ai_decide(input, questions)`             | `STRUCT` with each answer, its probabilities, and confidence  |

All functions take `model => 'name'` and `on_error => 'fail' | 'null'` (default `'fail'`). Spice checks constant arguments, such as labels and levels, when it plans the query. It does this before it calls a model.

A new `POST /v1/decisions` endpoint gives the same answers over an OpenAI-compatible API. `POST /v1/nsql` also accepts `reasoning_effort`. `rerank()` now uses evaluation models, with a strategy for each query. See [#14838](https://github.com/spiceai/spiceai/pull/14838), [#15040](https://github.com/spiceai/spiceai/pull/15040), [#14852](https://github.com/spiceai/spiceai/pull/14852), and [#14782](https://github.com/spiceai/spiceai/pull/14782).

### Iceberg Without a Catalog

An Iceberg dataset can read a table directly from object storage or the local filesystem. `from` is the table root on `file://`, `s3://`, `s3a://`, `gs://`, or `gcs://`.

To always read the current table, set only `from`. Spice finds the current metadata file on every query and every refresh. It uses `metadata/version-hint.text` when the file exists. Otherwise it uses the metadata file with the highest version number.

```yaml
datasets:
  - from: iceberg:s3://my-bucket/warehouse/db/taxis
    name: taxis
    params:
      iceberg_s3_region: us-east-1
```

To read one fixed version, pin the metadata file with `iceberg_metadata_path`. The path is relative to `from`, or a full URL. Pinned tables are read-only:

```yaml
datasets:
  - from: iceberg:s3://my-bucket/warehouse/db/taxis
    name: taxis
    params:
      iceberg_s3_region: us-east-1
      iceberg_metadata_path: /metadata/00003-8f2c.metadata.json
```

The earlier `metadata_path` parameter still works, but logs a deprecation warning.

Other Iceberg changes in this release:

- The Hadoop catalog finds the committed metadata version.
- Loading a catalog keeps nested child namespaces.
- Glue loads tables from S3 buckets that have dots in the name.
- Scans decode batches at the session `batch_size`.

See [#15081](https://github.com/spiceai/spiceai/pull/15081), [#15095](https://github.com/spiceai/spiceai/pull/15095), [#15142](https://github.com/spiceai/spiceai/pull/15142), [#15105](https://github.com/spiceai/spiceai/pull/15105), [#15053](https://github.com/spiceai/spiceai/pull/15053), and [#15072](https://github.com/spiceai/spiceai/pull/15072).

### Shared State Location (`runtime.state`)

- **Startup check**: An instance with `runtime.state` checks the location at startup. It needs write access. It refuses to start on a store that ignores conditional writes, or on a store that holds a newer state format. Until the check passes, the instance is not ready. The check records the state format in `_spice/format.json`.
- **A folder for each feature**: Each feature writes under its own folder of the location: `cluster/`, `rate-control/`, and `results-cache/`. See [Breaking Changes](#breaking-changes).
- **Snapshots**: With `runtime.state` set, acceleration snapshots go to the `snapshots/` folder. They no longer need their own location. A `snapshots.location` setting takes priority.

```yaml
runtime:
  state:
    location: s3://my-bucket/spice/

datasets:
  - from: postgres:orders
    name: orders
    acceleration:
      enabled: true
      engine: cayenne
      mode: file
      snapshots: enabled
```

Each snapshot publish also gets its own object name, so two publishes in the same second no longer overwrite each other. See [#15138](https://github.com/spiceai/spiceai/pull/15138), [#15036](https://github.com/spiceai/spiceai/pull/15036), [#15117](https://github.com/spiceai/spiceai/pull/15117), and [#15028](https://github.com/spiceai/spiceai/pull/15028).

### SQL Results Cache TTL

The SQL results cache now behaves like a standard TTL cache. A refresh, a CDC batch, or a retention pass no longer invalidates cached results. Before this change, each refresh made every hot key a miss at the same time, and this caused a burst of query executions.

- An entry ages from the start of the query that produced it. Time spent in the queue counts.
- An entry is fresh while its age is at most `item_ttl`.
- Between `item_ttl` and `item_ttl + stale_while_revalidate_ttl`, Spice serves it as `STALE`. One background revalidation for each key replaces it.
- After that, the entry is a miss.

Entries also expire in insertion order, and a GET and a POST to the same HTTP path no longer share a cache entry. See [Breaking Changes](#breaking-changes), [#15033](https://github.com/spiceai/spiceai/pull/15033), [#14919](https://github.com/spiceai/spiceai/pull/14919), and [#14884](https://github.com/spiceai/spiceai/pull/14884).

### Cayenne

- **Runtime-wide tuning**: `runtime.adaptive_tuning` (`enabled` or `disabled`, default `disabled`) replaces the `cayenne_tuning` parameter. `runtime.params.target_replication_lag`, `target_freshness`, `target_query_latency`, `target_convergence_window`, and `target_qph` replace the `cayenne_goal_*` parameters. See [Breaking Changes](#breaking-changes) and [#14844](https://github.com/spiceai/spiceai/pull/14844).

  ```yaml
  runtime:
    adaptive_tuning: enabled
    params:
      target_freshness: 30s
  ```

- **Settings apply on restart**: A changed acceleration setting now applies to the existing Cayenne acceleration when Spice restarts. Before, Spice logged a message to delete the acceleration, and a changed `partition_by` failed the dataset. Settings that change how rows are written, such as `cayenne_sort_columns` and `cayenne_compression_strategy`, apply in place. Settings that change what stored rows mean, such as `primary_key` and `partition_by`, rebuild the acceleration. See [#15094](https://github.com/spiceai/spiceai/pull/15094).
- **Faster keyed tables**: A keyed table builds its primary-key filter during its first load. It also bulk-loads without per-row routing and without a whole-table fold. See [#15099](https://github.com/spiceai/spiceai/pull/15099) and [#15076](https://github.com/spiceai/spiceai/pull/15076).
- **Position deletes**: `cayenne_deletion_mode: auto` can use position deletes for a small primary-key table on local storage (Linux, 8 or more physical cores). See [#15042](https://github.com/spiceai/spiceai/pull/15042).
- **Secondary indexes**: Index runs are always persisted, and an index stays complete across acceleration snapshots. CDC maintains the index for each operation type. A hash join reads each file once when it narrows an indexed table's scan. See [#14979](https://github.com/spiceai/spiceai/pull/14979), [#15068](https://github.com/spiceai/spiceai/pull/15068), [#14340](https://github.com/spiceai/spiceai/pull/14340), and [#14934](https://github.com/spiceai/spiceai/pull/14934).
- **Correctness**:
  - Cayenne refuses data stored under a different `partition_by`.
  - A keyed partition's append is published as a protected overlay.
  - Cayenne prepares every partition after a refresh.
  - Cayenne reclaims snapshot directories that a reload supersedes.
  - NaN values no longer cause incorrect pruning.
  - Deletion-index bounds and reload fencing are fixed.

  See [#15019](https://github.com/spiceai/spiceai/pull/15019), [#14955](https://github.com/spiceai/spiceai/pull/14955), [#15111](https://github.com/spiceai/spiceai/pull/15111), [#15069](https://github.com/spiceai/spiceai/pull/15069), [#14792](https://github.com/spiceai/spiceai/pull/14792), and [#14993](https://github.com/spiceai/spiceai/pull/14993).

### Rate Control and Responses API

- **Rate control**: Waiting requests are admitted in arrival order. After an origin outage, queued requests no longer wait out the whole `rate_control_acquire_timeout` while capacity is free. Components that share an origin are compared by their resolved settings. Instances that set different limits for one origin are held to the lowest limit. See [#14931](https://github.com/spiceai/spiceai/pull/14931), [#14937](https://github.com/spiceai/spiceai/pull/14937), and [#14932](https://github.com/spiceai/spiceai/pull/14932).
- **`/v1/responses`**: The endpoint runs Spice tools and honors `tool_recursion_limit` when it streams. It now returns each Spice tool call as an `mcp_call` item in `output`. A client that keeps its own history can replay these items. See [#14930](https://github.com/spiceai/spiceai/pull/14930) and [#15126](https://github.com/spiceai/spiceai/pull/15126).
- **Models**: Anthropic streaming works for responses that open with a thinking block. Spice drops empty Anthropic text blocks. A new `anthropic_workspace_id` parameter is available. An OpenAI model with an unknown service tier loads and serves. See [#14920](https://github.com/spiceai/spiceai/pull/14920), [#14834](https://github.com/spiceai/spiceai/pull/14834), [#14829](https://github.com/spiceai/spiceai/pull/14829), and [#14927](https://github.com/spiceai/spiceai/pull/14927).

### Other Fixes

- **Flight and Flight SQL**: Sessions authenticate before they bind, and TLS handshakes have a time limit. Query and data errors return `InvalidArgument`, not `Internal`. A prepared-statement schema matches the stream when parameters are bound. See [#15128](https://github.com/spiceai/spiceai/pull/15128), [#14956](https://github.com/spiceai/spiceai/pull/14956), and [#15106](https://github.com/spiceai/spiceai/pull/15106).
- **Federation and pushdown**: Pushed-down `INTERSECT` and `EXCEPT` match NULL rows. DuckDB and SQLite pushdown is corrected for `string_agg ORDER BY`, `concat` with NULLs, and decimal `AVG` and `SUM`. DuckDB unparses backslash-quote string literals exactly. Vortex scans no longer receive casts that Vortex cannot evaluate. See [#15110](https://github.com/spiceai/spiceai/pull/15110), [#14798](https://github.com/spiceai/spiceai/pull/14798), [#14888](https://github.com/spiceai/spiceai/pull/14888), [#15083](https://github.com/spiceai/spiceai/pull/15083), [#14985](https://github.com/spiceai/spiceai/pull/14985), and [#15096](https://github.com/spiceai/spiceai/pull/15096).
- **Search**: `vector_search` returns its top `k` rows by score on chunked and multi-vector columns. RRF keeps named arguments on nested search calls. See [#15056](https://github.com/spiceai/spiceai/pull/15056) and [#14975](https://github.com/spiceai/spiceai/pull/14975).
- **CDC and acceleration**: PostgreSQL CDC keeps applying changes after a source column type changes. A `changes` dataset without a primary key is rejected when it loads. A failed acceleration build no longer keeps the dataset down until restart. Rows that retention evicted stay out of the `on_zero_results` fallback. Each failing dataset logs its load failure. See [#15037](https://github.com/spiceai/spiceai/pull/15037), [#14960](https://github.com/spiceai/spiceai/pull/14960), [#14942](https://github.com/spiceai/spiceai/pull/14942), [#14783](https://github.com/spiceai/spiceai/pull/14783), and [#14939](https://github.com/spiceai/spiceai/pull/14939).
- **Connectors**: ClickHouse loads `LowCardinality`, `DateTime64`, `Array`, `Map`, `Tuple`, `Enum`, 128-bit integer, and IP columns. SharePoint lists drive items when a listing contains a folder. Drasi forwards CDC creates and snapshots as upserts, and reports forward delivery metrics. The Hugging Face connector retries Hub responses that break off part way. See [#14953](https://github.com/spiceai/spiceai/pull/14953), [#14946](https://github.com/spiceai/spiceai/pull/14946), [#14791](https://github.com/spiceai/spiceai/pull/14791), [#15075](https://github.com/spiceai/spiceai/pull/15075), and [#15009](https://github.com/spiceai/spiceai/pull/15009).
- **Performance**: The optimizer estimates selective `IN` lists and OR-of-equalities from the number of distinct values (NDV). See [#14140](https://github.com/spiceai/spiceai/pull/14140).
- **Other**: `host.cpu.count` reports the configured CPU count. The MCP server and `/v1/decisions` have fixes. The HTTP connector rejects a `request_path` that URL parsing would rewrite. See [#15108](https://github.com/spiceai/spiceai/pull/15108), [#15041](https://github.com/spiceai/spiceai/pull/15041), and [#14965](https://github.com/spiceai/spiceai/pull/14965).

## Breaking Changes

> TODO(DRI): confirm each item below with the PR authors.

**`runtime.state` uses a folder for each feature.** State that an rc.1 instance wrote at the location root is not read. The scheduler now uses `cluster/`, rate control uses `rate-control/`, and SQL results-cache warmup uses `results-cache/`. An explicit `runtime.scheduler.state_location` keeps its earlier layout. Move the objects into the new folders, or accept that the instance starts without its earlier state.

**`runtime.state` is checked at startup.** An instance does not become ready until its location accepts writes and conditional writes. See [Shared State Location](#shared-state-location-runtimestate).

**SQL results cache entries age on TTL.** A refresh no longer invalidates them. A query can return cached data that is older than the latest refresh, for up to `item_ttl` (plus `stale_while_revalidate_ttl`, when set). Reduce `item_ttl` if you need results to follow refreshes more closely.

**Cayenne tuning settings are renamed.** Replace the `cayenne_tuning` parameter with `runtime.adaptive_tuning` (`adaptive` becomes `enabled`, `auto` becomes `disabled`). Replace the `cayenne_goal_*` parameters with the `runtime.params.target_*` settings. `runtime.adaptive_tuning` accepts only `enabled` or `disabled`. Other values, including `true`, fail the Spicepod load.

**Pinned Iceberg tables are read-only.** An Iceberg dataset with `iceberg_metadata_path` set to a `.json` file fails to load with `access: read_write`. The `metadata_path` parameter is deprecated.

**Acceleration setting changes apply on restart.** Spice used to log a message and keep the old settings. It now applies a changed setting, and some changes (for example `primary_key` or `partition_by`) rebuild the acceleration.

## Upgrading

To upgrade to v2.4.0-rc.2 once the release artifacts are available, use one of the following methods:

**CLI**:

```console
spice upgrade v2.4.0-rc.2
```

**Homebrew**:

```console
brew upgrade spiceai/spiceai/spice
```

Homebrew follows the version published in the tap. Use the explicit CLI version or Docker tag to select this release candidate.

**Docker**:

Pull the `spiceai/spiceai:2.4.0-rc.2` image:

```console
docker pull spiceai/spiceai:2.4.0-rc.2
```

For available tags, see [DockerHub](https://hub.docker.com/r/spiceai/spiceai/tags).

**Helm**:

```console
helm repo update
helm upgrade spiceai spiceai/spiceai --version 2.4.0-rc.2
```

**AWS Marketplace**:

Spice is available in the [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jmf6jskjvnq7i). Marketplace availability follows its published versions.
